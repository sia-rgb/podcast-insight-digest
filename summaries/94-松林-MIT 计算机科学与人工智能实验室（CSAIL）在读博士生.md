## 一、访谈主题概览

- 动态稀疏注意力机制：讨论 DeepSeek Native Sparse Attention 和 Kimi MoBA 如何实现由查询动态决定稀疏模式，并将其应用于预训练阶段。
- 线性注意力与混合架构：分析 MiniMax 01 采用线性注意力与 Softmax 注意力交替堆叠的混合设计，以及其窗口式算法的训练效率。
- 硬件高效的算法设计原则：强调算法需优先适配 GPU 硬件特性（如 Tensor Core、连续读取、矩阵乘法），而非追求数学优雅。
- 国内大模型公司技术路径对比：比较 DeepSeek、Kimi、MiniMax 在注意力优化上的不同哲学——硬件暴力美学 vs 极简设计 vs 混合验证。

- 模型能力提升新范式：提及推理时计算投入（Test Scaling）与预训练架构创新的关系。

## 三、核心观点、讨论主题与案例

### 观点一：Native Sparse Attention 在预训练中全面超越 Full Attention，令人意外

- **核心判断**：DeepSeek 提出的 Native Sparse Attention（NSA）不仅在推理阶段加速，还在预训练 loss 和下游任务上优于 Full Attention，打破了“稀疏注意力必然导致性能下降”的固有认知。
- **具体解释**：NSA 通过动态块选择（Block Selection）和压缩注意力分支提供全局梯度，使模型在训练中注意力更集中、冗余更少。短序列（8K-16K）已能获得明显加速，且效果不输甚至超过全注意力。
- **案例或依据**：嘉宾提到“Native Sparse Attention 甚至比 Full Attention 要好”，并引用文本中“在预训练 Loss、下游任务和推理上全面压制 Full Attention”。消融实验显示，若删除压缩注意力分支（退化为不可导的块选择），效果劣化至低于 Quest。

### 观点二：将动态稀疏注意力用于预训练需要解决梯度回传问题，DeepSeek 和 Kimi 各有方案

- **核心判断**：动态稀疏注意力的关键困难在于块选择是不可导的离散操作，此前工作（如 Quest）主要限于推理。DeepSeek 和 Kimi 分别通过压缩分支和混合切换解决了预训练中的梯度流动。
- **具体解释**：DeepSeek 在 NSA 中引入压缩注意力分支（Compressed Attention），对每个 token 压缩 KV 后计算注意力，输出提供梯度指导块选择，使整个流程可微。Kimi MoBA 则删去压缩分支，通过 SFT 阶段将最后三层切换为 Full Attention 来补偿梯度稀疏问题。
- **案例或依据**：文本中明确说明“Quest 用于推理可能掉点，而 DeepSeek 不掉点”。Kimi 在知乎博客详细记录了 SFT 时 hybrid approach 的心路历程。

### 观点三：硬件高效性是注意力算法能否落地和 Scale up 的核心门槛

- **核心判断**：无论算法在数学上多优美，如果不适配 GPU 硬件（如 Tensor Core、连续内存读取、避免 HBM 瓶颈），很难在大模型上获得实际收益。
- **具体解释**：设计者需优先考虑“凑矩阵乘法”以利用 Tensor Core 加速，并减少随机内存访问。DeepSeek NSA 通过强制 GQA 组内所有注意力头选择相同 KV 块，将读取开销降至最低；MiniMax 的窗口算法也将训练拆解为矩阵乘法，契合硬件。
- **案例或依据**：文本以 Flash Attention 的分块策略为例：在 Full Attention 中，每个 query block 顺序扫描所有 KV block（连续读取无浪费）；但在 SPA 中，不同 query 需求不同，若仍用连续读入，最坏情况需读入所有 token 并集，造成低效。因此 NSA 采用每个 token 独立计算 output，牺牲部分矩阵乘并行性但避免多余读取。

### 观点四：Kimi MoBA 追求极简设计，但付出粒度和短序列加速代价

- **核心判断**：Kimi 的设计哲学是砍掉冗余分支（压缩注意力、窗口注意力），仅保留核心块选择。这种极简换来实现简单，但也导致块大小必须较大（512 token），top-k 选择较少（top-3），短序列加速不明显。
- **具体解释**：由于块大小 512，每 token 只选 3 个块，粒度较粗；短序列（<128K）的优势不突出。SFT 时存在梯度稀疏问题，需在最后三层切换为 Full Attention 来弥补。而 DeepSeek 块大小 64，top-16，短序列即加速，且压缩分支提供了全局梯度，SFT 无需额外处理。
- **案例或依据**：文本对比了两者数字：DeepSeek block size 64, top-16；Kimi block size 512, top-3。Kimi 已在产品中上线 MoBA，证明极简路线仍可实际落地，但嘉宾认为其局限性明显。

### 观点五：MiniMax-01 首次将线性注意力混合架构 Scale up 到 GPT-4 级别，验证了该路线的可行性

- **核心判断**：MiniMax-01 采用 Hybrid 架构（7 层线性注意力 + 1 层 Softmax 注意力重复 10 遍，共 80 层），证明了线性注意力在大模型上的有效性，此前学术界多限于小规模验证。
- **具体解释**：线性注意力（去掉 Softmax，改写为矩阵乘法可实现 State Expansion）理论复杂度是线性的，但过去因硬件不高效而未广泛采用。MiniMax 通过窗口算法（Chunkwise Algorithm）结合并行与循环模式，实现了 Exact 的训练，复杂度次二次，适用于超长序列。
- **案例或依据**：文本提到 MiniMax-01 的 Lightning Attention 实现，以及窗口算法与 Mamba-2 的 block decomposition 等价。嘉宾认为该工作将线性注意力领域的关注度提升至新高度。

### 观点六：国内大模型公司敢于进行架构创新且成果显著，将影响全球人才流向

- **核心判断**：DeepSeek、Kimi、MiniMax 等公司在注意力机制上连续产出高质量论文和落地系统，展示出与海外比肩甚至超越的创新能力，这会增强海外留学生回国发展的吸引力。
- **具体解释**：这些工作并非简单跟随，而是在硬件适配、预训练方案、效率与效果平衡上做出独特贡献。开源与论文发布也提升了技术影响力和投资者信心。
- **案例或依据**：文本结尾指出“国内技术已肉眼可见地追赶甚至超越，这将对海外留学生增加吸引力”。嘉宾个人排名中，NSA 最为亮眼，Kimi 次之，MiniMax 虽排最后但肯定其有效性。

### 观点七：动态稀疏注意力与线性注意力目标一致但路径不同，稀疏注意力在长文本可靠性上更“安全”

- **核心判断**：动态稀疏注意力和线性注意力都旨在降低长文本训练和推理的计算复杂度，但稀疏注意力保留全部 KV 缓存（只稀疏化计算），而线性注意力改变机制。在长文本任务的稳定性和下限方面，稀疏注意力更安全。
- **具体解释**：稀疏注意力不丢弃 KV，因此不会损失上下文信息；线性注意力通过状态压缩可能丢失部分检索能力。Hybrid 架构用少量 Softmax 注意力层弥补这一缺陷。MiniMax 证明了混合是可行解，但稀疏注意力直接保留全量 KV，下限更高。
- **案例或依据**：文本指出“Sparse Attention 因保留全部 KV 缓存，在下限和长文本能力上更‘安全’”。嘉宾对比两者目标时明确提到这一判断。

## 四、关键术语表

- **Full Attention（全注意力）**：标准注意力机制，计算所有 token 对之间的注意力权重，复杂度为 O(n²)。
- **Sparse Attention（稀疏注意力）**：只让部分 token 进行交互，降低计算量。分为静态稀疏（模式固定）和动态稀疏（由查询决定模式）。
- **动态稀疏注意力（Dynamic Sparse Attention）**：查询动态决定关注哪些键值块，通常先对 KV 分块压缩，再按块选择。代表性工作有 Quest、DeepSeek NSA、Kimi MoBA。
- **线性注意力（Linear Attention）**：通过变换（如去除 Softmax 并改写为矩阵乘法）使复杂度与序列长度成线性关系。常结合 State Expansion 和分块训练。
- **GQA（分组查询注意力，Grouped Query Attention）**：多个查询头共享一组键值对，减少 KV 缓存大小，现代大模型常用（如 Llama、千问）。
- **Block Selection（块选择）**：在动态稀疏注意力中，以固定大小的连续 KV 块为单位进行选中或忽略，便于硬件连续读取。
- **Compressed Attention（压缩注意力）**：对每个 token 的 KV 进行压缩后计算注意力，输出用于提供梯度信号以指导不可导的块选择（DeepSeek NSA 专用分支）。
- **Chunkwise Algorithm（窗口算法）**：一种线性注意力的训练方法，将序列切分成块，块内用并行矩阵乘法，块间用循环模式传递隐藏状态，复杂度次二次，适用于超长序列。
- **State Expansion（状态扩展）**：线性注意力通过将隐藏状态从向量（D 维）扩充为矩阵（D×D 维）来增加记忆容量，比传统 RNN 的向量状态更硬件高效。
- **Tensor Core**：GPU 上专用于快速计算半精度矩阵乘法的计算单元，速度远超通用 ALU，是现代 GPU 加速的核心单元。
- **Memory Wall（内存墙）**：当计算速度（如 Tensor Core）远超内存带宽时，数据加载成为性能瓶颈的现象。算法设计需尽量让数据加载连续且可复用，以避免内存墙。
